--------------------------------------------------------------------------------
1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
A BLDC motor controller firmware for a RC vehicle drivetrain.

Hardware:
  Board       : ST B-G431B-ESC1 (STM32G431CBU6, Cortex-M4, 170 MHz)
  Motor       : 3-phase BLDC, sensorless FOC, ~3100KV
  Bus voltage : 12 V nominal
  Host        : Raspberry Pi 5 connected via USART2

Purpose:
  The STM32 acts as a UART-controlled ESC node.
  RPi5 sends normalized commands u ∈ [-1.0, +1.0].
  STM32 runs closed-loop FOC and streams back telemetry (~10 Hz).

SDK: ST Motor Control SDK v6.4.1 (sensorless, speed mode, STO observer + PLL)
IDE: STM32CubeIDE (Eclipse-based), project at motor_test1_20260227/STM32CubeIDE/

Two STM32CubeIDE configurations, switched via BUILD_ESC preprocessor define:

  Configuration | BUILD_ESC defined? | Purpose
  --------------|-------------------|-------------------------------------------
  Release       | YES               | RPi5 ESC firmware — flash for deployment
  Debug         | NO                | Motor Pilot tuning — ASPEP enabled

Key compiler flags:
  -Ofast -g3 -mfpu=fpv4-sp-d16 -mfloat-abi=hard -mcpu=cortex-m4

Base defines: ARM_MATH_CM4, USE_HAL_DRIVER, STM32G431xx

To add BUILD_ESC in STM32CubeIDE (Release config only):
  Project → Properties → C/C++ Build → Settings
  → MCU GCC Compiler → Preprocessor → Defined symbols → add BUILD_ESC
  → Set configuration to "Release" → Apply and Close → Rebuild

Flash artifacts:
  STM32CubeIDE/Release/motor_test1_20260227.elf  ← RPi5 deployment
  STM32CubeIDE/Debug/motor_test1_20260227.elf    ← Motor Pilot tuning

What BUILD_ESC controls in each file:
  mc_tasks.c            : #ifdef skips ASPEP_start() in Release
  mc_app_hooks.c        : #ifdef enables full ESC state machine + UART init
  stm32_mc_common_it.c  : #ifdef calls ESC_COMM_UART_RxISR() + clears ASPEP flags

5. COMMUNICATION PROTOCOL (USART2, 1843200 baud, 8N1)
--------------------------------------------------------------------------------
Command frame  RPi5 → STM32  (5 bytes):
  [0xAA] [cmd_lo] [cmd_hi] [0x00] [XOR_chk]
  cmd = int16_t, scaled: -32768 = -1.0, +32767 = +1.0
  checksum = XOR of bytes [1]..[3]

Telemetry frame  STM32 → RPi5  (10 bytes):
  [0xBB] [spd_lo] [spd_hi] [state] [faults] [u_lo] [u_hi] [v_lo] [v_hi] [XOR_chk]
  speed  = int16_t RPM (average, signed)
  state  = ESC_State_t byte (0..6)
  faults = lower byte of MC_GetCurrentFaultsMotor1()
  u      = int16_t raw command currently active (-32768..+32767)
  v      = uint16_t DC bus voltage in whole Volts
  checksum = XOR of bytes [1]..[8]

ESC state byte values:
  0=BOOT  1=WAIT_NEUTRAL  2=READY  3=FORWARD  4=BRAKE  5=REVERSE  6=FAULT

UART architecture:
  RX: RXNEIE enabled directly via USART2->CR1 in ESC_COMM_Init().
      ESC_COMM_UART_RxISR() called from USER CODE BEGIN 0 of USART2_IRQHandler.
      Self-synchronising SOF search — no alignment loss on garbled bytes.
      HAL_UART_Receive_IT CANNOT be used (the project's IRQ handler is custom LL).
  TX: Direct register polling (TXE per byte, no TC wait).
      10 bytes ≈ 43 µs at 1843200 baud — safe inside 1 ms task cycle.

In Debug build:
  ASPEP/MCP owns USART2, Motor Pilot connects via ST-Link VCP (same physical port).
  ESC_COMM layer is compiled out. Motor Pilot sends speed/torque commands directly.

6. ESC STATE MACHINE (mc_app_hooks.c)
--------------------------------------------------------------------------------
States and transitions:
  BOOT         → WAIT_NEUTRAL    always (one-shot at startup)
  WAIT_NEUTRAL → READY           when |u| < deadband (host confirmed neutral)
  READY        → FORWARD         when u >  deadband AND MC_StartMotor1() ok
  READY        → REVERSE         when u < -deadband AND MC_StartMotor1() ok
  FORWARD      → READY           when |u| < deadband OR 500 ms timeout
  FORWARD      → BRAKE           when u < -deadband (sign reversal)
  REVERSE      → READY           when |u| < deadband OR 500 ms timeout
  REVERSE      → BRAKE           when u >  deadband (sign reversal)
  BRAKE        → FORWARD         when MCSDK=IDLE AND u >  deadband
  BRAKE        → REVERSE         when MCSDK=IDLE AND u < -deadband
  BRAKE        → READY           when MCSDK=IDLE AND |u| < deadband
  any          → FAULT           when MCSDK fault detected (faults != 0 or FAULT_NOW/OVER)
  FAULT        → WAIT_NEUTRAL    when MCSDK reaches FAULT_OVER (auto-acknowledged)

Key parameters:
  ESC_MAX_SPEED_RPM    15000  — |u|=1.0 maps to this RPM
  ESC_MIN_SPEED_RPM    3000   — firmware floor = OBS_MINIMUM_SPEED_RPM (observer handoff)
  ESC_RAMP_MS          100    — speed ramp duration per command (ms)
  ESC_NEUTRAL_DEADBAND 0.02f  — |u| below this treated as neutral
  ESC_TIMEOUT_MS       500    — stop motor if no command for 500 ms
  ESC_TELEMETRY_EVERY  100    — one telemetry frame every 100 hook calls (~10 Hz)

Safety:
  esc_cmd_value initialised to 0x7FFF (non-neutral) → WAIT_NEUTRAL blocks until
  the host explicitly sends a neutral frame. Motor cannot start on power-on.

Hook is called every ~1 ms from MC_APP_PostMediumFrequencyHook_M1() (mc_tasks.c).

7. MOTOR PARAMETERS
--------------------------------------------------------------------------------
Motor type     : 3-phase BLDC, sensorless FOC, ~3100KV
Pole pairs     : 2
Rs             : 0.1 Ω (stator resistance)
Ls (firmware)  : 5 µH  [NOTE: true measured value is ~1 µH, but 1 µH makes the
                         discrete-time observer unstable at 25 kHz FOC rate.
                         τ=Ls/Rs=10µs < Ts=40µs → C1/F1>1 → unstable.
                         Using 5 µH gives C1/F1=0.8 (stable). Tune Kp/Ki in
                         Motor Pilot to compensate the detuned current loop.]
Ke             : 0.25 V_rms ph-ph / kRPM (Motor Pilot identification result)
Nominal current: 2 A peak
Max speed      : 15000 RPM
Bus voltage    : 12 V nominal

Observer limits (hardware-verified):
  Min reliable speed  : ±2500 RPM (BEMF physics floor, hardware-verified bench)
  Firmware speed floor: ±3000 RPM (ESC_MIN_SPEED_RPM = OBS_MINIMUM_SPEED_RPM)
  Drivetrain no-load  : ±3000 RPM verified with wheels off ground (Motor Pilot)
  Disturbance test    : NOT YET performed (hand-stop under load)
  Observer handoff    : 3000 RPM during rev-up (OBS_MINIMUM_SPEED_RPM)
  Full stall faults   : axle locked by external load → Speed Feedback fault
                        This is a physics constraint of sensorless FOC, not a bug.

PWM frequency  : 25 kHz
FOC rate       : 25 kHz (REGULATION_EXECUTION_RATE=1)
Speed loop rate: 1 kHz

Current loop PID (in drive_parameters.h):
  Kp=1235, Ki=1975 (scaled for Ls=5µH firmware model; base values at Ls=1µH
  were Kp=247, Ki=395; ×5 for inflated Ls model)
  Tune live with Motor Pilot after startup is confirmed.

8. HARDWARE PERIPHERALS (STM32G431CBU6 on B-G431B-ESC1)
--------------------------------------------------------------------------------
TIM1       : 6-channel PWM, 3-phase motor drive
ADC1/ADC2  : Phase current + DC bus voltage sensing
USART2     : RPi5 link — 1843200 baud (Release) / Motor Pilot (Debug)
COMP1/2/4  : Analog comparators for overcurrent protection
OPAMP1/2/3 : Signal conditioning for current sense amplification
CORDIC     : Hardware sin/cos accelerator for FOC
DAC3       : Debug/monitoring output

Pin/clock config: motor_test1_20260227/motor_test1_20260227.ioc
  WARNING: regenerating from CubeMX overwrites HAL init files.
  Always keep custom code inside USER CODE sections to survive regeneration.

10. HOW TO SET UP ON A NEW PC
--------------------------------------------------------------------------------
Requirements:
  - STM32CubeIDE 1.16.x or later (free from st.com)
  - ST Motor Control Workbench 6.4.1 (optional, for parameter changes)
  - ST-Link V3 USB-JTAG (built into the B-G431B-ESC1 board)
  - Git (for version control)
  - Python 3 + pyserial (for tests/esc_test.py)

Steps:
  1. Clone / copy the repo to C:\01_Fixed\08_stm_ws_2601
     (or adjust paths — STM32CubeIDE project paths are relative)

  2. Open STM32CubeIDE → File → Open Projects from File System
     → Navigate to motor_test1_20260227/STM32CubeIDE → Import

  3. Verify two configurations exist: Debug and Release

  4. Confirm BUILD_ESC is defined ONLY in Release configuration:
     Right-click project → Properties → C/C++ Build → Settings
     → MCU GCC Compiler → Preprocessor → Defined symbols
     Release: BUILD_ESC must be present
     Debug:   BUILD_ESC must NOT be present

  5. Build Release → flash with ST-Link (Run → Run Configurations or drag .elf)

  6. Test with:
     cd tests/
     pip install pyserial
     python esc_test.py
     (Edit PORT = 'COMx' to match your ST-Link VCP port in Device Manager)

  7. For Motor Pilot tuning: build and flash Debug config, then connect with
     ST Motor Control Workbench to the same COM port at default baud (115200).
